# Beans and grind size

The web dashboard has a bean picker and grind size input. Manage beans under
**Beans** in the navigation, or follow **Manage beans** from the dashboard.
Each entry requires a roaster and name. Multiple entries with the same name can
represent different bags. Roast date is no longer shown or required; existing
`roastDate` fields are preserved, and older clients can still send a valid date.

The machine remembers the selected bean and each bean's last saved grind size.
A bean with no saved setting is prefilled with the most recently saved grind
size, when available. This suggestion must be saved before brewing. Grind size
is optional until first saved, and accepts numbers from 1.0 to 16.0
in increments of 0.1. Press **Save** after changing the grind size, before brewing.
Switching beans restores that bean's saved value. Removing the selected bean
clears the selection. Controls are disabled during an active process.

On the display's brew screen, the caption above the profile selector shows a
small bean icon, the selected bean's name, and its saved grind setting. The
profile selector still works as before. This caption updates after bean or grind
changes from either the display or web UI. A bean without a saved value shows
`Grind -`; an empty selection shows `No bean selected`.

The library is stored on internal LittleFS as `/beans.json`, including when shot
history is stored on an SD card. Changes write a temporary file before replacing
the library, and report storage errors to the UI. Up to 100 entries are supported;
roaster and name are limited to 100 bytes each.

## WebSocket requests

All requests include `tp` and `rid`. Responses use the matching `res:beans:*`
type and `rid`. Successful responses include `beans`, `selectedId`, and optional `lastGrindSetting`. Failed
responses include `error`. Successful mutations broadcast `evt:beans:changed`
with `beans`, `selectedId`, and `lastGrindSetting` so connected dashboards stay synchronized.

- `req:beans:list`: read the library and current selection.
- `req:beans:save`: send `bean: {roaster, name}`. Omit `id` or use
  an empty string to add an entry; send an existing `id` to edit one. Editing
  preserves its remembered grind size. IDs are generated by the machine.
- `req:beans:delete`: send the entry's `id`.
- `req:beans:select`: send `id` and optionally a numeric `grindSetting`.
  An empty `id` clears the selection. Invalid grind settings reject the entire
  request without changing the library or selection.

Example:

```json
{
  "tp": "req:beans:select",
  "rid": "example",
  "id": "1",
  "grindSetting": 6.1
}
```

## Shot history

At brew start the firmware snapshots the selected bean and saved grind size.
This applies to shots started from the web UI, touchscreen, or other controller
inputs. Utility flushes and discarded short shots do not create bean notes.

The snapshot is saved beside the recorded `.slog` in its notes JSON:

```json
{
  "id": "000001",
  "beanId": "1",
  "beanType": "Example Roaster — Colombia",
  "bean": {
    "id": "1",
    "roaster": "Example Roaster",
    "name": "Colombia",
    "roastDate": "2026-09-28",
    "grindSetting": 6.1
  },
  "grindSetting": "6.1"
}
```

`beanType` and `grindSetting` retain compatibility with existing notes editors
and exports. The full `bean` snapshot preserves the roast date and original
identity even if the library entry is later edited or removed. Shot History
shows beans and grind size in the collapsed shot card; the analyzer
also shows the saved fields. The binary shot and index formats are unchanged.

Notes use six-digit filenames consistently. Reads and index rebuilds also
support legacy unpadded notes filenames.

## Display controls

The start menu's coffee bean button opens a left/right selector of up to ten
recently added or selected beans. Select commits the previewed bean; Back leaves
it unchanged. Older libraries start with the newest beans and the selected bean.
The web UI remains available for the full library and adding/editing beans.

After a non-utility brew ends (including a manually stopped shot), the display
asks **Next grind?** for the bean captured at brew start. Arrows adjust by 0.1
between 1 and 16; Save persists the next-shot value, and Skip discards the draft.
The default is that bean's current saved grind, falling back to the last known
grind or 1.0 if none has ever been saved. This does not rewrite the finished
shot's notes. No prompt appears without a selected bean or after a utility flush.

`req:beans:grind` accepts `id` and `grindSetting` to update a bean without changing
`selectedId`. Lists and mutation replies also include `recentIds` (newest first,
maximum ten). Existing clients can ignore it. Successful mutations made from
both the display and the web UI broadcast `evt:beans:changed`.

Simulator integration checks: after building `display-sim`, run
`scripts/test_display_beans.sh`. Alternatively, run its `program` with
`--test-beans` **from an empty temporary directory**; the checks create test beans
in that directory's `sim_data`. On headless Linux use `SDL_VIDEODRIVER=dummy
SDL_RENDER_DRIVER=software`.
