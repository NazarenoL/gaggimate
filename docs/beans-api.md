# Beans and grind size

The web dashboard has a bean picker and grind size input. Manage beans under
**Beans** in the navigation, or follow **Manage beans** from the dashboard.
Each entry has a roaster, name, and roast date. Roast date is stored as
`YYYY-MM-DD`. Multiple entries with the same name can represent different bags.

The machine remembers the selected bean and each bean's last saved grind size.
Grind size is optional until first entered, and accepts numbers from 1.0 to 16.0
in increments of 0.1. Press **Save** after changing the grind size, before brewing.
Switching beans restores that bean's saved value. Removing the selected bean
clears the selection. Controls are disabled during an active process.

The library is stored on internal LittleFS as `/beans.json`, including when shot
history is stored on an SD card. Changes write a temporary file before replacing
the library, and report storage errors to the UI. Up to 100 entries are supported;
roaster and name are limited to 100 bytes each.

## WebSocket requests

All requests include `tp` and `rid`. Responses use the matching `res:beans:*`
type and `rid`. Successful responses include `beans` and `selectedId`. Failed
responses include `error`. Successful mutations broadcast `evt:beans:changed`
with `beans` and `selectedId` so connected dashboards stay synchronized.

- `req:beans:list`: read the library and current selection.
- `req:beans:save`: send `bean: {roaster, name, roastDate}`. Omit `id` or use
  an empty string to add an entry; send an existing `id` to edit one. Editing
  preserves its remembered grind size. IDs are generated by the machine.
- `req:beans:delete`: send the entry's `id`.
- `req:beans:select`: send `id` and optionally a numeric `grindSetting`.
  An empty `id` clears the selection. Invalid grind settings reject the entire
  request without changing the library or selection.

Example:

```json
{
  "tp": "req:beans:select",
  "rid": "example",
  "id": "1",
  "grindSetting": 6.1
}
```

## Shot history

At brew start the firmware snapshots the selected bean and saved grind size.
This applies to shots started from the web UI, touchscreen, or other controller
inputs. Utility flushes and discarded short shots do not create bean notes.

The snapshot is saved beside the recorded `.slog` in its notes JSON:

```json
{
  "id": "000001",
  "beanId": "1",
  "beanType": "Example Roaster — Colombia",
  "bean": {
    "id": "1",
    "roaster": "Example Roaster",
    "name": "Colombia",
    "roastDate": "2026-09-28",
    "grindSetting": 6.1
  },
  "grindSetting": "6.1"
}
```

`beanType` and `grindSetting` retain compatibility with existing notes editors
and exports. The full `bean` snapshot preserves the roast date and original
identity even if the library entry is later edited or removed. Shot History
shows beans, roast date, and grind size in the collapsed shot card; the analyzer
also shows the saved fields. The binary shot and index formats are unchanged.

Notes use six-digit filenames consistently. Reads and index rebuilds also
support legacy unpadded notes filenames.
